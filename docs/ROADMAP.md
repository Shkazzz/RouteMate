# RouteMate — приоритетная дорожная карта развития

**Статус:** планируемые работы (не считать реализованными).  
**Платформы:** Android / iOS / Web (Flutter).  
**Базовый принцип:** сначала надёжная географическая основа, затем ИИ-планирование и дополнительные сервисы.  
**Плановая длительность:** примерно 15–21 неделя небольшой команды; оценки предварительные, зависят от инфраструктуры, тестирования и состава команды.

## 1. Видение продукта

RouteMate — персональный помощник в автомобильных путешествиях. Пользователь задаёт точки А и Б, состав путешественников (включая возраст детей), интересы, транспорт, ограничения времени и бюджета. Приложение ищет **реальные интересные места вдоль всей дороги**, сравнивает варианты отклонений, составляет план остановок и формирует маршрут для навигатора.

Ключевая ценность: не просто карта с маркерами, а пригодный к поездке маршрут с понятными причинами рекомендаций, временем, планом и ожидаемыми расходами.

## 3. Версия 0.3 — стабильность геоданных (P0)

**Цель:** убрать ошибки HTTP 502 / CORS / Failed to fetch как типичный пользовательский сценарий, обеспечить устойчивый доступ к достопримечательностям и корректно считать дополнительные расходы времени.

### Задачи
- [ ] Выделить единый backend API для Android, iOS и Web: клиент не обращается напрямую к нестабильным POI API.
- [ ] Использовать FastAPI + PostgreSQL/PostGIS для геозапросов и локального кэша.
- [ ] Реализовать географический коридор **по всей полилинии маршрута** с контролем плотности и устранением дублей.
- [ ] Собрать кэш каталога POI на основе лицензированных данных OSM; резервные источники применять при отказе основного.
- [ ] Ввести ограничение частоты, тайм-ауты, повтор запросов с backoff, наблюдаемость и понятные сообщения об ошибках.
- [ ] Оценивать **автомобильное время заезда и возврата**, а не только прямую дистанцию до полилинии.
- [ ] Добавить тесты длинных трасс, развязок, трасс с мостами, дорог с ограничением движения и плохого интернет-соединения.
- [ ] Обеспечить частичную выдачу рекомендаций при недоступности отдельных источников.

**Критерии приёмки:** маршрут остаётся доступным при отказе POI-поиска; ошибки диагностируются; на тестовых маршрутах POI определяются по всей дороге, а дополнительное время считается посредством дорожной маршрутизации. Тесты API и пользовательского сценария проходят в CI.

## 4. Версия 0.4 — персональный ИИ-планировщик (P1)

**Цель:** перейти от списка POI к плану поездки, который путешественник может редактировать.

### Задачи
- [ ] Расширить профиль: взрослые, возраст каждого ребёнка, питомцы, интересы, комфорт, тип транспорта.
- [ ] Варианты маршрутов: **«Быстро»**, **«Живописно»**, **«Семейный»**.
- [ ] Промежуточные обязательные точки с ручным изменением порядка.
- [ ] Система ранжирования POI: доступность, соответствие интересам, время заезда, длительность осмотра.
- [ ] Подключить ИИ через **серверный прокси** для объяснения рекомендаций. ИИ оценивает только найденные реальные места и не придумывает координаты, часы работы и безопасность.
- [ ] План по дням: старт, остановки, перерывы, обед, ночлег, предполагаемое прибытие.
- [ ] Повторный расчёт маршрута при добавлении, удалении или перестановке остановки.
- [ ] Локальное сохранение поездок, восстановление после перезапуска и редактирование.

**Критерии приёмки:** пользователь создаёт поездку с обязательными точками, получает план по дням, изменяет остановки, видит новое ETA и может открыть сохранённую поездку.

**Пример сценария:** 2 взрослых и ребёнок 7 лет едут Москва → Санкт-Петербург; интересы «Природа» и «Интерактивные музеи». Приложение рекомендует реальные семейные остановки с пояснением, рассчитывает реальный заезд, предлагает обед и отдых. Все времена — результат расчёта, а не заранее заданные значения.

- [ ] Поддержка электромобилей: зарядные станции и запас хода.
- [ ] Подбор кафе, туалетов, мест отдыха, гостиниц и кемпингов по критериям группы.
- [ ] Оценка бюджета: топливо, питание, ночёвки, развлечения, платные дороги.
- [ ] Пометки о достоверности данных: подтверждённые часы работы, неизвестное время, приблизительная стоимость.

**Критерии приёмки:** приложение показывает смету по статьям и предлагает полезные остановки без противоречий плану поездки.

- [ ] Экспорт GPX/KML и передача остановок в поддерживаемые навигационные приложения.

## 8. Целевая архитектура

```text
Flutter (Android / iOS / Web)
          |
          v
Backend API (FastAPI / Python)
  |       |        |         |
  v       v        v         v
PostGIS  OSRM/   OSM POI   AI proxy
+ cache  Valhalla catalog  (Gemini)
```

- **Flutter / Dart:** единый пользовательский интерфейс.
- **FastAPI:** единый серверный API, CORS-контроль, авторизация при необходимости, ключи, лимиты, диагностические сообщения.
- **PostgreSQL + PostGIS:** пространственный поиск и фильтрация POI вдоль линий маршрутов.
- **OSM + OSRM/Valhalla:** геоданные и маршрутизация с учётом условий лицензий и инфраструктуры.
- **Gemini AI (опционально):** объяснения и персональная сортировка реальных POI.
- **Кэш и резервирование:** меньше обращений к публичным API и более предсказуемая работа.

**Экономика:** библиотеки и наборы данных могут быть бесплатными, но серверы, хранение данных, маршрутизация и лимиты внешних моделей могут потребовать оплаты. На MVP использовать бесплатные и открытые решения, избегая зависимости от неограниченного доступа к публичным серверам.

## 9. Отложенные идеи (после 1.0)

- Совместные поездки: приглашения и голосование за остановки.
- Голосовой ассистент: «найди место для отдыха через 30 минут».
- История путешествий, фотографии и коллекции маршрутов.
- Подбор по доступности для маломобильных путешественников с проверкой источников.
- Общедоступные подборки маршрутов и авторские рекомендации.

## 10. Очерёдность и продуктовые показатели

**Последовательность:** 0.3 → 0.4 → 0.5 → 0.6 → 1.0. Не добавлять функции до устранения ошибок геоданных, мешающих основной ценности продукта.

Метрики для контроля:
- доля успешных запросов построения маршрута;
- доля успешных поисков POI;
- время ожидания первой подборки;
- процент поездок с выбранными остановками;
- доля поездок, сохранённых и повторно открытых;
- частота ошибок, лагов и отказов внешних источников.
